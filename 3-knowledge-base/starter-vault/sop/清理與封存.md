# SOP：清理與封存

> **何時讀這份**：要刪除、搬移、重新命名、批次整理檔案，或電腦磁碟空間突然變少時。

**鐵則：AI 不自動刪除、不自動搬移。流程是「提案 → 核准 → 執行 → 回報」，每一步都留紀錄。**

## 步驟

### 1. 提案（AI 做）

只讀、不動任何檔案，產出一份清單，每一項寫：

- 路徑與大小、最後修改日期
- 為什麼建議處理（重複、過期、已封存過、暫存檔）
- 建議做法：**優先順序是「保留 → 封存（移到封存資料夾）→ 丟回收桶 → 永久刪除」**，用最輕的一種
- 風險：有哪些檔案或連結會受影響（例如其他卡片的 wikilink 會斷）
- 能不能復原

### 2. 核准（使用者做）

使用者逐項看，或批次核准某一類。**沒有明確核准的項目，一律不動。**
下列情況要多問一次：數量比預期多很多、無法復原、牽涉到別人的檔案、屬於敏感資料。

### 3. 執行（AI 做，只做核准過的）

- 搬移與改名後，立刻檢查連結：全庫的 wikilink 還解析得到嗎？
- 不要用萬用字元一次刪一大批；一項一項或一個資料夾一個資料夾。
- 永久刪除前先確認有備份，且使用者知道「刪了就沒有了」。

### 4. 回報

寫進 [[CURRENT_HANDOFF]]：處理了哪些、跳過了哪些、磁碟上實際變化（回去數過）、有沒有連結受影響。
如果這個清理規則以後還會用到，寫進 [[DECISIONS]]。

## 完成檢查

- [ ] 沒有被核准的項目都沒被動過
- [ ] 全庫 wikilink 都還解析得到（存檔後檢查沒報斷鏈）
- [ ] 回報寫了「做了什麼」也寫了「沒做什麼」
