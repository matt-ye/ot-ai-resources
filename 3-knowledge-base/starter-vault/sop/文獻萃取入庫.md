# SOP：文獻萃取入庫

> **何時讀這份**：使用者要把論文（已發表文獻）的資訊整理進知識庫，例如做文獻回顧、統合分析的資料萃取，或為了出一組卡片。

**前提**：已發表文獻屬綠色（公開）。**未發表稿件、審查中的稿件、IRB 相關資料不在此列**，一律當紅，只能本機處理。

## 步驟

1. **先定問題**：一句話寫下要回答的問題與納入條件（例如對象、介入、結果指標），放在 `2_compression/<批次名>/` 的開頭。
2. **取得全文的合法管道**：開放取用的全文、機構訂閱的資料庫（由使用者自己登入並下載）。
   **AI 不要代替使用者繞過付費牆、不要使用來路不明的下載站**。拿不到全文，就只用摘要並註明「僅摘要層級」。
3. **每篇論文做一份萃取表**（`2_compression/<批次名>/` 一篇一列或一個檔），欄位至少有：
   書目資訊（作者、年、題名、期刊、卷期頁、DOI）、研究設計、對象與樣本數、介入、比較、結果指標、主要結果、限制、來源在原文的位置（頁碼或段落）。
4. **書目資訊不憑記憶**：作者名單、卷期、DOI 一律從原始頁面或文獻管理軟體複製；AI 補的書目要標 `來源未載，待補` 直到使用者核對。
   AI 常會編出看似真實的作者與 DOI。
5. **數字一律附位置**：每個數字旁邊寫它在原文的哪裡（表幾、第幾頁）。回不去的數字不要入庫。
6. **重要結論做第二次獨立檢查**：叫另一個全新的 AI（沒看過前面過程），只給它原文與萃取表，要它逐格核對。見 [[多代理交辦]]。
7. **入庫成卡**：每個獨立的方法或發現一張卡，格式見 [[建卡]]；`ip` 通常是 `他人需標註`（內容來自他人研究），卡內寫出處；
   不要把論文原文整段貼進卡，用自己的話重寫。
8. 更新 [[CURRENT_HANDOFF]]。

## 完成檢查

- [ ] 每筆書目都核對過原始來源
- [ ] 每個數字都有原文位置
- [ ] 重要結論有第二次獨立檢查
- [ ] 沒有整段貼上論文原文
