# SOP：建卡

> **何時讀這份**：使用者核准了建卡提案，要把精煉結果寫成 `cards/` 裡的知識卡時。

## 一卡一主張

一張卡只放**一個可以單獨拿來用的主張**。判斷方法：能不能用一句話說完，而且這句話在別的文章或簡報裡能單獨引用？
不能，就是摘要，不是卡。

**拆卡訊號**：證據區出現「第一章、第二章」；或同一張卡裡有超過一個框架的完整條列。出現時拆成多張卡，
細節留在 `2_compression/`。

## 卡片格式

檔名：用「一句話主張的簡短版」，可以用中文；不要用 `/ \ : * ? " < > |` 這些字元。
放進 `cards/` 底下符合知識性質的資料夾（看知識性質，不看素材來源）。

```
---
title: 一句話標題
created: 2026-11-25
type: 原則            # 原則、框架、技巧、定義 擇一
themes:
  - 主題一
maturity: "AI草稿"     # AI 寫的一律這個值
ip: 自有               # 自有、他人需標註、通用或公共領域
needs_evidence: false  # 有任何來源未載的地方就改 true
tags:
  - knowledge-atom
  - ai-draft
---

## 主張 Assertion
一到兩句。

## 理由 Reason
為什麼成立。

## 證據範例 Evidence
數字要寫分母與來源；回不到來源就寫「來源未載，待補」。

## 適用情境
什麼時候用、什麼時候不要用。

## 關聯
- 同類卡、上層地圖頁（用 wikilink）
```

必填欄位：`type`、`themes`、`ip`、`maturity`。缺一個，存檔後檢查會擋下。

## 規則

1. AI 寫的卡一律 `maturity: "AI草稿"` 加 tag `ai-draft`。升級由使用者審核後決定（見 [[審核草稿]]）。
2. 數字一定附分母與來源；沒有來源就不寫數字，或寫 `來源未載，待補` 並把 `needs_evidence` 設 true。
3. 使用者自己的推論，要寫「詮釋非實證，不可過度推論」。
4. `ip` 判斷：自己的想法與整理用 `自有`；引用他人教材或文獻的內容用 `他人需標註` 並在卡內寫出處；公共知識需用自己的話重寫，不照搬。
5. 每張新卡至少連到一張 MOC（地圖頁），並在該 MOC 加一行。
6. 建完後，存檔後檢查會自動跑；有回報問題就當下修，修完再繼續下一張。

## 完成檢查

- [ ] 每張卡只有一個主張
- [ ] 必填欄位齊全，`ip` 值合法
- [ ] 每個 wikilink 都指到存在的檔案
- [ ] MOC 已加連結
- [ ] [[CURRENT_HANDOFF]] 已記錄新增的檔案

## 你可以這樣說

> 建卡提案我核准了（照你列的清單）。請讀 sop/建卡.md，一張一張建，全部先標 AI草稿。
> 每建完一張，確認格式檢查沒有報錯，再做下一張；最後在 MOC 加連結並更新 handoff。
