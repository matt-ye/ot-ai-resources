# 多個 AI 一起工作的規則（簡化版）

## 為什麼需要這份

你可能會換工具、換對話視窗，或同時開兩個 AI。聊天內容不會自動留下來，所以：

> [!important] 核心原則
> 聊天不是系統紀錄。要交接的事必須寫進檔案；沒寫進檔案的進度，就當作沒發生。

## 角色

| 角色 | 做什麼 |
|---|---|
| 你（使用者） | 決定方向、判斷價值、授權敏感資料、最後核准 |
| 主 AI（編排者） | 拆任務、分派、整合、控制風險、最後驗收、更新交接檔 |
| 執行 AI（子代理） | 在指定範圍內讀取、研究、產出，只回報結論與證據 |
| 獨立查核者 | 全新開啟、沒看過前面過程的 AI，專門檢查高風險判斷與批次修改 |

不綁定特定模型。依任務需要的判斷力、成本與是否能碰敏感資料來選。

## 每次開工

1. 讀 [[CLAUDE]]（其他 AI 工具讀自己的入口檔，內容應指向同一份規則）。
2. 讀本檔與 [[CURRENT_HANDOFF]]。
3. 讀 [[MOC 總圖]] 與相關領域 MOC。
4. 先回報：查到什麼、假設什麼、查不到什麼。
5. 有未結案任務時，先判斷是接手、暫停，還是問你；不要另開衝突工作。

## 任務登記與檔案鎖

[[CURRENT_HANDOFF]] 同一時間只放一個主任務，至少記：

- `task_id`：`YYYY-MM-DD-短名稱`
- `owner`：`user`、AI 名稱，或 `unassigned`
- `status`：`ready`、`in_progress`、`waiting_user`、`blocked`、`done`
- `locked_files`：現在只有這位寫入者能改的檔案；沒有就寫 `[]`
- `claimed_at`：登記時間（`YYYY-MM-DDTHH:mm`）

**一檔一寫者**：同一個檔案不能同時由兩個 AI 修改。同步工具（雲端硬碟等）不會替你合併。

**鎖有期限**：預設 8 小時。過了還沒更新 `claimed_at`，視為被中斷的 session 忘了放掉，
接手者在 handoff 記一行「接管逾期鎖（原 owner、原時間）」就可以接手。
例外：`status: waiting_user` 是在等人，不適用逾時接管。

## 品質防線

- **存檔後檢查（hook）**：每次寫入 `.md` 後，`scripts/` 裡的程式自動檢查 BOM、衝突標記、
  frontmatter、卡片必填欄位、`ip` 值、斷掉的 wikilink。有問題會把原因回報給 AI，要當下修。
- hook 只看格式。**內容是否忠於來源，要靠獨立查核者或你自己**——兩者互補。
- hook 內部壞掉時採「放行不擋人」，所以偶爾要跑 `scripts/hook_selftest.py` 確認它還有效。

## 什麼時候 AI 可以自己接手

四個條件同時成立才行：

1. handoff 的 `next_owner` 是自己；
2. `status: ready`；
3. `owner: unassigned`；
4. 要改的檔案都不在別人的 `locked_files` 裡。

接手時先把 `owner` 改成自己、`status` 改 `in_progress`、列出 `locked_files`，再動手。

**仍要你明確點頭的事**：碰敏感資料、刪除、移動、批次改名、發布、對外同步，或任何高風險修改。

## 交接怎麼交

交出控制權前，目前的 owner 必須：

1. 存好所有成品。
2. 列出新增、修改、刪除的檔案（不能只寫「如聊天所述」）。
3. 記下做過哪些驗證與結果。
4. 分清楚哪些是事實、哪些是推論、哪些還沒驗證。
5. 寫出下一個最小動作。
6. 把 `owner` 改成接手者或 `unassigned`，放掉不再需要的鎖。

## 發現衝突時

同步衝突副本、檔案時間怪怪的、或兩邊內容不一致時：停止寫入 → 兩個版本都留著、不覆蓋不刪 → 寫差異摘要與合併建議 → 高風險內容交給你決定。

用 git 的話：只有逐條追加的日誌（如 [[DECISIONS]]）可以用 union 合併；卡片、MOC、handoff 這類有 frontmatter 的檔案
不要用 union（會產生重複欄位而且不報錯），一律三方合併並由人看過。

## 知識庫產出

- 遵守 [[CLAUDE]] 的一卡一主張與 IP 規則。
- AI 產物要標成熟度與證據狀態，不假裝是你的定稿。
- 專案層級的決定寫進 [[DECISIONS]]。
- 大批次作業，每個子代理的範圍要互斥（做法見 [[多代理交辦]]）。
