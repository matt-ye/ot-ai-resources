# ① 規劃：先寫「專案說明書」再動手

> 授權：程式 MIT、文件 CC BY-NC 4.0。

## 這是什麼

大量萃取最常見的失敗，不是程式寫錯，而是**一開始沒講清楚「做到哪裡算完」**：沒有停止條件、沒有預算、不知道哪些資料不能送出去。「專案說明書」（正式名稱是專案憲章）就是一頁紙，把這些事在開工前寫死。

## 你需要先準備什麼

- 一個你想回答的問題（例如「這 5 篇 RCT 的 FMA-UE 前後測數字是什麼」）。
- 文字編輯器（記事本、VS Code、Obsidian 都可以）。
- 如果要請 LLM 幫你起草：任一個你有權使用的 LLM 對話視窗。**不要把未發表資料、可辨識個人的資料貼進去**（見範本的「資料分級」）。

## 檔案

| 檔案 | 用途 |
|---|---|
| `專案說明書_範本.md` | 空白範本，八個欄位，每欄有填寫提示 |
| `專案說明書_示範_中風上肢5篇.md` | 範本填好的示範版（5 篇中風上肢 RCT） |

## 逐步 SOP

1. **（人★）定題目與範圍。** 在哪裡做：自己的筆記。寫成一句話：要萃取「什麼欄位」、從「哪一類論文」。預期：一句話能被同事複述。沒做到：還在擔心範圍太大，就先縮成 5 篇做示範。
2. **（LLM）請 LLM 起草。** 在哪裡做：LLM 對話視窗。貼上：「請依下列八個欄位幫我起草專案說明書，缺資訊的地方寫『待人補』，不要自己編數字：目標、範圍、紅線、停止條件、驗收標準、預算、資料分級、模型分工。我的題目是：（貼你的一句話）」。為什麼：LLM 擅長列出你忘了問的問題。預期：得到八欄草稿，有些欄寫「待人補」。
3. **（人★）把「待人補」全部補完。** 在哪裡做：`專案說明書_範本.md` 的副本。特別是停止條件、預算、資料分級三欄，一定要人決定。沒做到：這三欄空白就不要開工。
4. **（人★）核准。** 在說明書最下方寫日期與核准人。之後任何改動都用「日期化補充」，不要偷改原文。
5. **做完要回頭看。** 在 `06_iterate/` 發現的新規則，回寫到說明書的「紅線」或「驗收標準」。

## 哪裡用 LLM、哪裡一定要人

- LLM：只負責起草。
- 人★：停止條件、預算、資料分級、核准——這四件事 LLM 不能代替你決定。

## 限制

- 示範版裡的門檻（例如一致率多少以上）是**示範設定**，不是學術標準；你的題目要自己訂。
- 預算欄的金額與額度，依你的方案而不同，示範版沒有填實際金額（未確認）。
