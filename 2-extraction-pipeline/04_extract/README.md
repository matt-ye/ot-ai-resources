# ④ 開發：把「請 AI 萃取」做成可重複、可檢查的流程

> 授權：程式 MIT、文件 CC BY-NC 4.0。

## 這是什麼

這一階段要做出三樣東西：**萃取提示**（告訴 LLM 怎麼抽、抽哪些欄位）、**欄位 schema**（規定輸出長什麼樣，用程式檢查）、**驗證程式**（輸出不合格就退回）。重點是：LLM 只負責「照原文抄」，不負責「算」。

## 你需要先準備什麼

- `01_plan/` 說明書與 `03_sources/` 驗證過的全文（文字檔；表格請轉成以 `|` 分隔的列）。
- Python 3.9 以上。
- 至少一個你有權使用的 LLM 帳號；做 `05_verify/` 時需要第二個、不同公司的 LLM。
- 名詞：schema＝規定資料欄位與格式的設計圖；JSON＝程式常用的資料格式；工作單（Issue）＝記錄「這件事要做、做到怎樣才算完成」的單子；測試＝用已知答案檢查程式的小程式。

## 檔案

| 檔案 | 用途 |
|---|---|
| `萃取提示_範本.txt` | 給 LLM 的提示，有 `{{PMID}}` 與 `{{TEXT}}` 兩個填空 |
| `extraction_schema.json` | 欄位 schema（JSON Schema 格式） |
| `validate_extraction.py` | 用 schema 檢查 LLM 輸出（只用標準庫） |
| `json_to_numbers_csv.py` | 把 JSON 結果整理成只有數字的長格式 CSV（去掉原文引句） |
| `examples/numbers_long.csv` | 5 篇的萃取數字（說明見 `examples/README.md`） |
| `tests/` | `validate_extraction.py` 的測試 |

## 逐步 SOP

1. **（人★）開工作單並寫完成標準。** 在哪裡做：GitHub 的 Issues（或任何待辦清單）。一張工作單寫一件事，例如「萃取 5 篇的 FMA-UE」，完成標準直接抄說明書的「驗收標準」。為什麼：讓「做完」可以被檢查。
2. **（LLM＋人★）調整提示與 schema。** 把 `萃取提示_範本.txt` 的結果、欄位換成你的題目；LLM 可以幫你改寫，但**欄位定義要人拍板**。每個欄位問自己：原文會直接印出這個數字嗎？如果要算才有，就不要放進欄位。
3. **（程式）確認驗證程式與測試能跑。** 在哪裡做：終端機，進到 `04_extract`。貼上：`python -m unittest discover -s tests`。預期：最後一行 `OK`。
4. **（LLM）小批試跑，只看方向。** 先拿 5 篇或更少。把 `{{PMID}}` 與 `{{TEXT}}` 換成實際內容貼給 LLM，把輸出存成 `<PMID>.json`。**小批的結果只能判斷方向，不能用來估算全批的效果**：原專案中 20 篇試跑看起來進步 19 個百分點，全批只剩約 5 個百分點。
5. **（程式）驗證格式。** 貼上：`python validate_extraction.py extraction_schema.json 你的json資料夾`。預期：每個檔案顯示 `[合格]`；不合格會列出缺哪個欄位。沒看到：LLM 常加 ```` ``` ```` 或前後說明文字，要求它「只輸出 JSON」重做。
6. **（LLM）全批萃取。** 每次只送一篇，不要把多篇混在同一個對話裡。失敗的篇要記錄（見 `06_iterate/`），不要靜默跳過。
7. **（程式）產出只有數字的 CSV。** 貼上：`python json_to_numbers_csv.py --model 模型A 資料夾A --model 模型B 資料夾B --out numbers.csv`。為什麼：去掉原文引句，方便分享與比對。
8. **（人★）審查後合併。** 程式與提示的修改一律經人看過再放進正式版本。

## 哪裡用 LLM、哪裡一定要人

- LLM：改寫提示、小批與全批萃取。
- 程式：驗證格式、整理 CSV、測試。
- 人★：定義欄位、寫完成標準、審查合併。

## 限制

- `validate_extraction.py` 只檢查**格式**（欄位在不在、型別對不對），不檢查數字對不對。數字對不對是 `05_verify/` 的事。
- schema 把所有數值當字串保存（照原文），是為了避免程式自動四捨五入。
- 提示裡的「quote」要求是給人核對用；公開分享時請去掉（用 `json_to_numbers_csv.py`）。
