# ⑤ 驗證：萃取完成不等於萃取正確

> 授權：程式 MIT、文件 CC BY-NC 4.0。

## 這是什麼

LLM 萃取會出錯，而且出錯時語氣一樣有自信。這一階段用四種互相獨立的方式找錯：

1. **第二條管線**：用另一個模型（或另一種方法）再做一次，逐格比對。
2. **陰性對照**：拿「不該有答案」的論文給同一套流程，看它會不會憑空編出答案。
3. **沒參與的代理重算**：請一個沒看過你過程的新對話，獨立重算你的統計數字。
4. **人抽查原文**：人回原文，對照數字。

四種方式都有 SOP 與 prompt：`SOP_01_第二條管線.md`、`SOP_02_陰性對照.md`、`SOP_03_沒參與的代理重算.md`、`SOP_04_人抽查原文.md`。

## 你需要先準備什麼

- `04_extract/` 的兩份獨立萃取結果（JSON 資料夾，或整理好的 `numbers_long.csv`）。
- Python 3.9 以上。

## 檔案

| 檔案 | 用途 |
|---|---|
| `compare_extractions.py` | 兩個模型逐格比對（CSV 或 JSON 皆可；JSON 有沒有引句都行） |
| `tests/test_compare.py` | 測試，含「重現 110 格」 |
| `SOP_01`～`SOP_04` | 四種驗證的做法與提示 |
| `人工裁決紀錄_空白範本.csv` | 人工裁決時填寫的空白表 |

## 逐步 SOP

1. **（程式）重現示範結果。** 在哪裡做：終端機，進到 `2-extraction-pipeline/05_verify`。貼上：
   `python compare_extractions.py --csv ../04_extract/examples/numbers_long.csv --labels 模型A 模型B --out compare_report.md`
   為什麼：確認你的環境得到與本專案相同的數字。預期看到：`比對 110 格：一致 82、不一致 8、都 Unclear 20；一致率 91%（分母 90）`。一致率 = 82 ÷（82＋8）= 91%；都 Unclear 的 20 格不放進分母。沒看到：確認路徑；Mac 把 `python` 改 `python3`。
2. **（程式）跑測試。** 貼上：`python -m unittest discover -s tests`。預期：最後一行 `OK`（含「重現 110／82／8／20」那一條）。
3. **（程式）對你自己的資料。** 把 `--csv` 換成你的檔，`--labels` 換成 CSV「模型」欄裡的兩個名字；或用 JSON 資料夾：`python compare_extractions.py --dir-a 資料夾A --dir-b 資料夾B --out report.md`。
4. **（人★）處理「不一致」清單。** 打開 `compare_report.md` 最上面的「不一致清單」，每一格回原文看，依 `SOP_04` 把裁決寫進空白範本。**本專案不替你判斷誰對誰錯。**
5. **（人★）抽查「都 Unclear」。** 兩個模型都說沒有，可能是原文真的沒報，也可能兩邊都漏。
6. 依 `SOP_01`～`SOP_03` 補做第二條管線之外的查核。
7. **（程式）通過才更新數字。** 全部裁決完成、不一致格都有紀錄，才把最終數字寫進分析檔。

## 比對規則（想改就改 `compare_extractions.py`）

- 數字：取第一個數字比，必須**完全相等**（`12.30` 與 `12.3` 算一致；不容許誤差，因為提示禁止換算）。
- 一邊 Unclear、一邊有數字：算「不一致」（可能是漏抓，也可能是編的，都要人看）。
- 兩邊都 Unclear：「都 Unclear」，不算錯。
- 離散類型（SD／SE／IQR）是文字，單獨逐字比：同一個數字被標成 SD 還是 SE，合併時權重差 √n 倍，是最危險的錯之一。
- 組別靠「組序」對齊（第 1 組對第 1 組），所以兩邊組數不同時，多出來的組會被算成不一致。

## 哪裡用 LLM、哪裡一定要人

- LLM：第二條管線、陰性對照、沒參與的代理重算。
- 程式：比對與統計。
- 人★：所有「不一致」格與抽樣原文核對。

## 限制

- 一致率 91% **不是準確率**。兩個模型可能犯同樣的錯（例如都讀錯同一個表）。
- 示範用 5 篇，樣本太小，不能推論到別的題目或別的模型。
- 本資料夾不含人工裁決的結果，也不指出 8 個不一致格哪一邊對。
