# config/：關鍵字設定檔怎麼寫

這個資料夾放「雷達要找什麼」。程式本身不用改，只改設定檔。
設定檔是 JSON 格式（純文字、用 `{ }` 和引號的資料格式）。用記事本、VS Code 都能改，存檔請選 UTF-8。

## 檔案

| 檔案 | 用途 |
|---|---|
| `literature-watch.ot.json` | 職能治療主題：原本四個（中風上肢、中風職能治療、失智症職能治療、長者跌倒預防），加上用表單新增、經人核准的主題（每個新主題都帶 `_來源` 與自己的 `rubric`），可直接用 |
| `literature-watch.example-autism.json` | 完全不同主題的範例（自閉症兒童），看它示範怎麼換題目 |
| `literature-watch.template.json` | 空白範本，每個欄位旁都有 `_說明_` 註解 |

名稱以底線開頭的鍵（例如 `_說明_query`）是註解，程式會忽略。
GitHub 自動執行時讀的是 **`config/literature-watch.json`**：把你選好的檔案複製一份、改成這個名字（見根目錄 README 的 B 段）。

## 逐欄解釋

### `days_window`：往回看幾天
月報用 45。每月 1 號跑一次，往回看 45 天，會和上個月的範圍重疊約兩週，目的是不漏掉剛好落在交界的論文；重疊造成的重複由程式去重，你不用處理。
想改成每週跑，就改成 10 左右，並把 workflow 的排程改成每週（見 README）。

### `max_per_topic`：每個主題最多掃描幾篇
Europe PMC 依發表日由新到舊回傳。超過這個數字的較舊論文**不會**被掃到，報告會明寫「只掃描了最新 N 篇（共 M 篇）」。
看到這句話有兩種處理：調大這個數字，或把查詢句寫得更精確（較好）。建議 6 到 10。

### `intro`：報告開頭那句話
給讀報告的人看的說明，例如「這份報告給誰、讀完要做什麼」。

### `rubric`：AI 的保留／篩掉判準

整份設定一個 `rubric`；**每個主題也可以有自己的 `rubric`**（寫在該主題裡，和 `query` 同一層），有寫的主題用自己的，沒寫的沿用整份的。用 PICO 表單新增的主題，都會帶自己的判準。
（`advanced/` 的進階流程用自己的讀事實提示，不使用 `rubric`，主題判準在那裡不生效。）
只有開啟 AI 篩選時才用到。怎麼寫：

1. 用英文寫（模型讀英文摘要最穩；報告上的理由會自動用繁體中文顯示）。
2. 先寫 **KEEP**：什麼研究設計（隨機對照試驗、系統性回顧……）、測什麼介入、報告什麼結果指標、對象是誰。
3. 再寫 **DROP**：沒有結果的研究計畫書、個案報告、純機制或影像研究、與介入無關的論文。
4. 不用寫輸出格式，程式會自動補上。
5. 寫得越具體越準。沒寫 `rubric` 的話，AI 只會篩掉明顯離題的。

寫完先用 `--triage` 跑一次，打開報告裡「AI 篩掉」那個收合區塊，看有沒有好論文被誤殺；有就把判準放寬。

### `topics`：主題清單
每個主題四個欄位，其中 `manual_also`／`note` 是選填。

- `id`：英文代號，小寫加底線，不要重複。離線測試檔用它對應主題。
- `label`：報告上顯示的名稱，中文即可。
- `query`：Europe PMC 查詢句，寫法如下。
- `manual_also`（選填）：字串清單，提醒讀者「這個主題也請另外手動查」的資料庫，會原樣列在報告裡；搭配 `note`（一句說明）。

#### 查詢句怎麼寫
- `TITLE:詞`：只比對標題。**這是降低雜訊最重要的一招**：不限標題的話，同一個主題一個月可能多出幾百篇不相干的論文。
- 同義詞放括號、用 `OR`：`TITLE:(stroke OR "cerebrovascular accident")`。
- 片語用雙引號：`"upper limb"`。
- 不同概念用 `AND` 接起來：病人族群 AND 介入方法。
- 萬用字元 `*`：`Alzheimer*` 同時找 Alzheimer 與 Alzheimer's。
- 限定研究設計可加在最後：`AND (randomized OR "systematic review")`。這個詞不加 `TITLE:` 時會搜標題＋摘要。
- JSON 裡的雙引號要寫成 `\"`（反斜線加雙引號），否則整個檔案讀不了。

#### 怎麼確認查詢句寫得對
1. 到 Europe PMC 網站（europepmc.org）的搜尋框貼上同一句，看筆數合不合理（一個月幾篇到幾十篇）。
2. 筆數太多：加 AND 條件或限定 `TITLE:`。筆數是 0：拿掉一個條件，或檢查拼字。
3. 再用本機跑一次（根目錄 README 的 A 段）確認報告長相。

### `ledger`（進階，選填）
只有 `advanced/` 的「事實對照帳本」流程才用，見 `advanced/README.md`。一般使用不要放。
